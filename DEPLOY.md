# Акниет — запуск на сервере

Стек в Docker Compose:

| Сервис    | Что делает |
|-----------|------------|
| `nginx`   | Отдаёт сайт (`index-stone.html` → главная, `projects/`, `technology/`, `map/`), админку `/admin`, проксирует `/api`, HTTPS |
| `backend` | Node.js + TypeScript (Express): заявки, контент, Telegram |
| `db`      | PostgreSQL 16, наружу не открыта |
| `certbot` | Продлевает сертификат Let's Encrypt раз в 12 часов |

## Первый запуск

1. На сервере нужны Docker и Docker Compose, порты 80 и 443 открыты. В DNS домена `akniet-home.kg` нужны две A-записи на IP сервера: `akniet-home.kg` (`@`) и `www.akniet-home.kg` (`www`). Адрес с www перенаправляется на основной.
2. Скопировать проект на сервер и создать `.env`:
   ```sh
   cp .env.example .env
   nano .env   # пароли, LETSENCRYPT_EMAIL, при желании Telegram
   ```
3. Поднять стек — сайт сразу заработает по HTTP:
   ```sh
   docker compose up -d --build
   ```
4. Выпустить сертификат — после этого nginx сам переключится на HTTPS:
   ```sh
   ./scripts/init-letsencrypt.sh
   ```

## Страницы сайта

| Адрес | Исходник | Что на странице |
|-------|----------|-----------------|
| `/` | `index-stone.html` | Главная: почему с нами выгодно, проекты, «под ключ», калькулятор, технологии, этапы, блок для инвесторов, вопросы, заявка |
| `/projects/` | `projects/index.html` | Готовые проекты с планировками и кейсы |
| `/technology/` | `technology/index.html` | Несущий металлический каркас и материалы отделки |
| `/map/` | `map/index.html` | Карта объектов и список мест |
| `/extras/` | `extras/index.html` | Бани, модульные дома, беседки, площадки — без цен, заявка на консультацию |
| `/invest/` | `invest/index.html` | «Под аренду»: почему выгодно, калькулятор окупаемости (режим аренды включён), примеры аренды из админки, проекты, вопросы |
| `/catalog/` | `catalog/index.html` | Каталог проектов для клиентов: обложка, по странице на проект (фото, характеристики, планировки), «что входит», контакты. Кнопка «Скачать PDF» — печать в PDF (A4). Закрыт от поисковиков (`noindex`), в sitemap не входит |

Общие стили — `site.css` (в корне, рядом с главной), общий скрипт — `assets/site.js`, 3D-логотип в подвале — `assets/logo3d.js`. Шапка, подвал и форма заявки повторяются на каждой странице: при их правке поменять во всех шести файлах (у каталога своя короткая шапка).

Кыргызские страницы `/ky/…` собираются из русских и словаря `i18n/ky.json`: `node scripts/build-ky.mjs` (при сборке Docker-образов это происходит само). Новые тексты, которых нет в словаре, скрипт перечислит — их нужно добавить в `ky.json`.

Посмотреть сайт локально с теми же адресами, что на сервере: `node scripts/build-ky.mjs && node scripts/dev-server.mjs` → http://localhost:8080 (другой порт: `PORT=8099 node scripts/dev-server.mjs`). Контент из админки там не подставляется.

## Обновление сайта

После правок страниц, `site.css`, `assets/site.js`, картинок или админки:
```sh
docker compose up -d --build nginx backend
```
Backend тоже пересобирается: он отдаёт страницы с контентом из админки и берёт их HTML из своего образа.

## Смена домена

Поменять `DOMAIN` в `.env` (без `www`), затем `docker compose up -d nginx backend` и снова `./scripts/init-letsencrypt.sh`. Если `SITE_URL` задан вручную — поменять и его, иначе canonical и sitemap останутся со старым адресом.

Если запись `www` добавили в DNS уже после выпуска сертификата — просто ещё раз запустить `./scripts/init-letsencrypt.sh`, он добавит www в сертификат.

## Админка

`https://<домен>/admin/` — логин и пароль из `ADMIN_USER` / `ADMIN_PASSWORD` (basic auth в nginx).
После смены пароля в `.env`: `docker compose up -d nginx`.

| Вкладка | Что редактируется |
|---------|-------------------|
| Заявки | Заявки с сайта, статусы: новая / в работе / готово / спам |
| Основное | Цена за м², цены открытой и закрытой террасы за м² ($300 и $350; пустое поле — этот вид террасы на сайте не предлагается), гарантия (лет), средний и минимальный срок стройки (мес), домов построено (пусто — карточка скрыта), лет строим (по умолчанию 6), подписчики Instagram |
| Контакты | Телефон, WhatsApp, Telegram (номер или @username), почта, Instagram — меняются во всех местах сайта |
| Проекты | Проекты на странице «Проекты и кейсы»: фото, стиль, название, площадь, спальни, санузлы, этажи, описание, площадь и тип террасы (открытая / закрытая), своя цена (или площадь × цена за м² + терраса × цена её вида), галочка «На главной» и планировка по этажам — комнаты с размерами и живым превью схемы (отметка «терр.» рисует комнату как террасу) или загруженная картинка этажа. Добавить, удалить, поменять порядок. Площади проектов — кнопки калькулятора «Как в проектах» |
| Кейсы | Построенные дома: фото, место, заголовок, площадь, срок, сезон, история, ссылка на проект. Нет ни одного кейса — блок скрыт |
| Вопросы | «Частые вопросы» на главной (видно 4, остальные по кнопке). В ответе можно писать `{price}`, `{terrace_open_price}`, `{terrace_closed_price}`, `{months}`, `{months_min}`, `{warranty}` — подставятся значения из «Основного» |
| Постройки | Страница «Постройки» (/extras/) и раздел «Не только дома» на главной: направления (бани, модульные дома, беседки, площадки) — обложка, название, коротко для главной, описание, пункты «что делаем», примеры работ с фото. Добавить, удалить, поменять порядок. Цены нет — «после консультации» |
| Аренда | Примеры домов клиентов, которые сдаются посуточно (страница «Под аренду»): фото, заголовок, место, проект, площадь, цена за сутки, ночей в год, вложения, история. Выручку за год и окупаемость сайт считает сам. Нет записей — блок скрыт |
| Материалы | 10 карточек раздела «Отделка из натурального дерева и камня» на странице «Технологии»: фото, категория, название, подзаголовок. Карточки по номерам, «Вернуть стоковую карточку» — сброс |
| Карта | Точки на странице «Карта объектов»: населённый пункт (рус/кыр), домов построено, общая площадь м². Нажатие на карту ставит точку, на точку — выбирает её |

- Пустое поле = значение из вёрстки (стоковое). Слова «год / года / лет», «месяц / месяцев» сайт подбирает сам.
- Фото загружаются с компьютера или телефона (JPG, PNG, WebP до 15 МБ); сервер сжимает их в WebP и хранит в томе `uploads`.
- Сайт подхватывает изменения в течение минуты.

Технически: числа на странице помечены `data-cms="<ключ>"`, ссылки — `data-contact="<ключ>"`, карточки — `data-slot="<номер>"`.
Новое поле: описать в `backend/src/content.ts` и пометить элемент в `index-stone.html`.

## SEO и серверный рендеринг

`/` и `/ky/` отдаёт backend: он берёт страницу (`index-stone.html`, `ky/index.html`), подставляет данные из админки
(цены, сроки, контакты, адрес, карточки, галерею, точки карты) и добавляет в `<head>`:

- `canonical`, `hreflang` (ru, ky, x-default), Open Graph и Twitter-карточки (картинки `assets/og/og-ru.jpg`, `og-ky.jpg`);
- JSON-LD: компания (`GeneralContractor`: адрес, координаты, часы работы, телефон, соцсети, цена за м²), сайт, страница, FAQ;
- коды подтверждения Google Search Console и Яндекс.Вебмастера, Google Analytics 4 и Яндекс.Метрику — если заданы в `.env`.

Страница кэшируется и пересобирается после любого сохранения в админке. Если backend недоступен, nginx отдаёт статическую копию — сайт продолжает работать.

Также: `robots.txt` и `sitemap.xml` (генерирует backend по `SITE_URL`), страница 404, иконки и `site.webmanifest`,
шрифты с собственного сервера (`assets/fonts`), 3D-сцена загружается после показа страницы.

После запуска на реальном домене:
1. Задать `SITE_URL` (или `DOMAIN`) в `.env`, при необходимости коды `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION`, `GA4_ID`, `YANDEX_METRIKA_ID`; затем `docker compose up -d backend`.
2. Добавить сайт в Google Search Console и Яндекс.Вебмастер, отправить `https://<домен>/sitemap.xml`.
3. Проверить разметку: https://search.google.com/test/rich-results и https://validator.schema.org.
4. Настроить цели (ниже).

### Цели аналитики

Сайт сам отправляет события в Google Analytics 4 (`gtag('event', …)`) и цели в Яндекс.Метрику (`reachGoal`) с одинаковыми названиями.
В Метрике: «Цели» → «Добавить цель» → «JavaScript-событие», идентификатор — название из таблицы.
В GA4: «Администратор» → «События» → отметить нужные как ключевые (key events) — хотя бы `lead_form`, `lead_quiz` и `lead_catalog`.

| Название | Когда срабатывает |
|----------|-------------------|
| `lead_form` | Отправлена форма заявки (параметры: `via` — способ связи, `type` — тип дома) |
| `lead_quiz` | Отправлена заявка из квиза «Подберём дом» |
| `lead_catalog` | Оставлен номер в форме «Получить каталог в WhatsApp» |
| `quiz_open` / `quiz_start` / `quiz_result` | Квиз открыт / дан первый ответ / показана подборка проектов |
| `contact_phone`, `contact_whatsapp`, `contact_telegram`, `contact_email` | Клик по телефону, WhatsApp, Telegram, почте (в любом месте сайта) |
| `contact_route`, `contact_social` | Клик «Маршрут в 2ГИС», переход в Instagram |
| `calc_use` | Посетитель начал пользоваться калькулятором (один раз за визит страницы) |
| `calc_rent` | Включён расчёт окупаемости посуточной аренды |
| `calc_estimate` | Нажата кнопка «Получить точную смету» в калькуляторе |
| `project_plan` | Открыта планировка проекта (параметр `project` — адрес проекта) |

У всех событий есть параметр `page` — страница, где оно произошло.
Заявка «Каталог проектов в WhatsApp» приходит в админку и Telegram со ссылкой на каталог — менеджер отправляет клиенту ссылку или PDF (открыть ссылку → «Скачать PDF» → «Сохранить как PDF»).
Квиз открывается кнопками «Подобрать дом за 1 минуту» и по ссылке с `#quiz` в конце, например `https://<домен>/#quiz` — удобно для рекламы и Instagram.

## Кыргызская версия (/ky/)

Русская страница `index-stone.html` — единственный исходник. Кыргызская `ky/index.html` собирается из неё и словаря `i18n/ky.json`:

```sh
node scripts/build-ky.mjs            # собрать и показать строки без перевода
node scripts/build-ky.mjs --extract  # строки без перевода в формате JSON — вставить в ky.json
```

При `docker compose up -d --build nginx` страница собирается автоматически.

- Поменяли русский текст в `index-stone.html` — добавьте перевод новой строки в `i18n/ky.json` (раздел `text`), иначе на /ky/ она останется по-русски; скрипт перечислит такие строки.
- `html` — фразы целиком вместе с тегами, где в кыргызском другой порядок слов; ключ — русский фрагмент как в исходнике.
- `js` — тексты для скриптов: окно планировки, калькулятор, сообщения формы.
- В админке у каждого текста карточек материалов и галереи два поля: РУС и КЫР. Пустое кыргызское поле при заполненном русском — на /ky/ показывается русский текст, а карточка помечена «нет перевода».
- Заявки с /ky/ помечены в админке «КЫР», в Telegram — «с кыргызской версии сайта».

## Telegram-бот

1. Создать бота у [@BotFather](https://t.me/BotFather) (`/newbot`), токен — в `TELEGRAM_BOT_TOKEN`.
2. Создать группу продавцов, включить «История чата для новых участников: видна», добавить бота.
3. `docker compose up -d backend` — при запуске backend сам подключает webhook (`https://<SITE_URL>/api/telegram/webhook`).
4. Отправить в группе `/chatid@<username_бота>` — бот ответит id группы. Вписать его в `TELEGRAM_CHAT_ID` и снова `docker compose up -d backend`.

Каждая заявка приходит в группу с кнопками:
- **✋ Беру** — заявка переходит в «В работе», в сообщении видно имя продавца; второй продавец взять её уже не сможет.
- **✅ Готово** — заявка закрыта. Пока заявка в работе, закрыть её может только тот, кто взял.
- **📋 Скопировать номер** — копирует телефон клиента (нужен Telegram, обновлённый после октября 2024).

Статус, поменянный в админке, обновляет сообщение в группе; «Новая» в админке снова показывает кнопку «Беру».
Пока переменные пустые, заявки только сохраняются в БД (в логах backend: `[telegram stub]`).
Кнопки работают только на сервере с публичным https-адресом (`SITE_URL`). `TELEGRAM_WEBHOOK_SECRET` можно не задавать — секрет выводится из токена.
После подключения webhook адрес `getUpdates` больше не работает — id группы узнавайте командой `/chatid`.

## API

| Метод | Путь | Доступ |
|-------|------|--------|
| POST  | `/api/leads` | публичный, 10 заявок в минуту с IP |
| GET   | `/api/content` | публичный |
| GET   | `/api/health` | публичный |
| GET   | `/api/admin/me`, `/api/admin/leads`, `/api/admin/content` | basic auth |
| PUT   | `/api/admin/content` | basic auth |
| PATCH | `/api/admin/leads/:id` | basic auth |

## Полезное

```sh
docker compose logs -f backend                   # логи
docker compose exec db psql -U akniet akniet     # консоль БД
docker compose exec db pg_dump -U akniet akniet > backup.sql   # бэкап БД
docker run --rm -v akniet_uploads:/u -v "$PWD":/b alpine tar czf /b/uploads.tgz -C /u .   # бэкап фото
```

(`akniet_` — имя папки проекта на сервере; точное имя тома: `docker volume ls`.)

Миграции БД лежат в `backend/migrations/*.sql` и применяются автоматически при старте backend.
